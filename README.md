# 秘封铁道纪行 · 初版 0.1

**Python 后端＋浏览器大屏与手机端。** 一台电脑主持，三名玩家连接同一局域网，通过手机浏览器加入。无需账号，无需 Node.js，运行时不依赖外网。

东方 Project 二次创作同人游戏，免费活动体验。已接入四张头像、三张结局 CG 和标题页插画；公共页面显示莲子的公开头像，隐藏身份使用未知头像。

## 现在开始

需要 Python 3.10 或更高版本。在项目目录运行：

```powershell
python -m pip install --target vendor -r requirements.txt
python run.py
```

当前工作区已安装二维码组件，直接 `python run.py` 即可。没有安装二维码组件时，仍可输入网址和房间码加入。

1. 电脑打开 **http://localhost:8000/host**，点击“创建房间”。可直接把主持页面投到大屏，也可打开工具栏的“观众屏”。主持页面保持前台运行。
2. 双击“启动游戏.bat”后，玩家打开 https://ddns2.mccolor.cc:8000/ 选择“持票入场”，或直接打开 https://ddns2.mccolor.cc:8000/join，输入房间码、昵称并准备。主持端二维码默认使用此公网地址；大屏“开局设置与网络地址”仍可切换局域网地址。
3. 三人都准备后，主持人在地图上方的独立控制栏点击“开始游戏并分配身份”，三人查看私密身份并确认路线，首程无限等待；主持人再点“正式发车”，或安排未确认者留站并发车。游戏时间从首日16:00开始推进，累计超过48小时仍未结束时触发超时结局（CG03）。尚未满足条件时，按钮保持可见，旁边显示加入与准备人数。
4. 结束后，可播放20秒真实行程回放、导出本局记录、同组重开或换组新开房。点击“创建新房间”后，已打开的观众屏自动跟随到新房间，独立浏览器也可同步；玩家手机仍保留旧局结局，需重新加入新房间。

端口占用时：`python run.py --port 8001`。只供本机开发时：`python run.py --bind 127.0.0.1`。退出服务按 Ctrl+C。

公网入口已保存在项目根目录 `server-config.json` 的 `publicUrl` 中，直接运行 `python run.py` 或双击“启动游戏.bat”都会加载。该配置将域名加入允许访问的地址，并设为默认二维码地址；主持人仍在本机通过 localhost 创建房间。可用 `--public-url https://其他域名:端口` 临时覆盖；将配置中的 `publicUrl` 设为 `null` 则仅使用局域网地址。修改后需重启游戏服务。HTTPS 由反向代理处理，代理上游使用本机 HTTP 8000 端口，并保留客户端的 Host（包括外部端口）和 Origin。

手机无法连接时，先手动访问大屏显示的地址。公网连接需确保 DDNS、HTTPS 证书和反向代理上游配置正确，且防火墙允许代理访问游戏服务；可用手机移动网络验证。局域网连接需检查是否同一 Wi-Fi 及是否启用客户端隔离。二维码的 `localhost/127.0.0.1` 只能在电脑自己打开。

## 已实现

- 可选“旅途回声”：主持控制栏开启后，第二日00:00起，梅莉／紫经过关联站点即可概率公开不同的官作短句，无需停车。同地点成功后随机抽一句，共16句。首句失败后概率40%→70%→100%，每地点组一次、每人最多两句、间隔2游戏小时；手机保留历史，赛后显示出处。新房间默认关闭，同组重开保留开关。详见[实现说明](design/旅途回声_实现说明_v0.7.md)。

- 100站、132条连接、35条可抽取游戏线路的全国全线网常驻；各线路独立配色，手机站点轴与大屏同色；头像直接覆盖最近到站的站点圆点，同站多名玩家纵向拼成胶囊，公开记录按身份、用户名两行等大显示。
- 线网采用水平、垂直和45°走线；干线站点对齐，区间内折点由187个减少至77个。京都—新大阪两线、濑户大桥走廊分别保留可见线路；交叉无圆点不换乘。
- 三席位、随机角色、十二组跨区域分散起点、私密手机页面；第四人无法占座。任意两人起点最短行车距离为5—10小时（游戏时间），已计入1小时特急捷径；不含中停和决策暂停。
- 仅显示游戏时间，累计超过48小时触发超时结局；到站后铁路暂停，玩家先当面讨论并私密确认路线，全部到站玩家确认后3秒自动继续，主持人可暂停自动继续，再手动继续或恢复倒计时；主持人也可安排未确认者留站并继续。每人每局一次请求留站，接受后锁定留站，拒绝后仍可选路线。留站满30分钟自动重新抽线，并再次暂停进入选路，不消耗改签次数。首程不限时，由主持人发车。中停15分钟继续原行程。所有旅途时长均为游戏内时长。
- 昼夜两套美术配色：06:00—18:00为暖米色、车厢蓝与紫色；18:00—次日06:00为深蓝与淡紫。大屏、观众屏和手机随游戏时钟同步切换。
- 莲子公开、梅莉／紫隐藏；服务器真实同站判定、秘密侵蚀、侵蚀后目标变化、三人相遇优先级；满足相遇条件结束，或由主持人中止。
- 东京⇄京都1小时特急；京都首夜两分支各一次50%；长野可重访20%远程停滞；奈良私密额外改签。
- 每次随机抽取一条本站可乘线路；若有其他线路，排除上一条线路，只有一条线路的站点仍保留返程，手机纵向站点轴列出沿线全部已收录站点和预计到达时刻，玩家可选本站两侧任意其他站点作为终点。途中可点击“下一站下车，重新选路”：完成当前区间后在下一站结束原行程，重新抽线并进入不限时选路，不消耗改签次数。中停期间申请则在下一次到站下车；未申请时继续原行程。
- 一次基础改签可以将抽到的线路换为本站另一条线路，选项显示全线起终点和本站相邻站，再自由选站；奈良奖励增加一次改签。卯酉特急进入东京／京都的可抽线路池，也可改签选择，不再额外固定发一张特急票。
- 行驶时手机仅显示到站运行倒计时与本人实时区间位置；其他人到站暂停时显示待确认座位，位置与倒计时同步冻结，全部确认后3秒自动继续，主持人可以暂停讨论。侵蚀等必要私密事件用临时提示传达。
- 刷新保留座位和状态；掉线5秒触发游戏时间与区间进度暂停，恢复后3秒继续，每次连续中断90秒无法恢复则中止；检测到断线后，在等待恢复的90秒期间显示返回本局二维码，超时中止后隐藏。
- 结局揭晓、真实已出发行程回放、结束后主持人导出日志、同组重开、开局前移除误入席位。
- 可开关的普通到站提示音。秘密事件没有公开声音、效果或角色颜色提示。

## 规则口径

沿用 [v0.3 设计稿](design/秘封铁道纪行_完整设计稿_v0.3.md) 和 [事件规范](design/站点事件与幻想线路_v0.3.md)。暂用设计默认值：首日16:00开始；只有所选终点暂停决策；未侵蚀三人同站优先判秘封胜；特急双向且所有角色可乘。

**当前实现优先于 v0.3 的七分钟时限和三张随机终点票建议。** 整局以累计游戏时间超过48小时作为超时条件，触发平局结局 CG03；选路和技术暂停期间不累计游戏时间。按15分钟结算，恰好48小时仍可会合，首次超时判定为第3日16:15，先于该时刻的到站和会合。一次抽一条线路，不再随机指定目的地，也不再截断为最多5个中间站。相邻走廊按游戏联程合并，线路由70条减为35条，双站线路由53条减为5条。每条线路是无分叉、无闭环的连续行程，玩家仍可双向选择沿线站点；原有站点、连接与中停保留。新增秋田—新潟（游戏4小时），接入奥羽・羽越日本海线；完整范围见[线路合并说明](design/线路合并说明.md)。颜色按线路固定，不表示角色。

确认目的地后，只沿本站至所选站的区间行驶，沿途游戏节点停靠15分钟；票面到达时刻包含等候、已生效停滞和沿途停靠。单边内部换乘余量已计入 CSV。后台仍按2秒推进15个游戏分钟的速度运行；界面统一显示小时、分钟与“第几日 HH:MM”，不显示内部刻数、真实剩余或真实行程秒数。到站剩余时间为游戏内小时:分钟，决策暂停期间冻结。选路不限时，停站玩家全部确认后显示3秒自动继续倒计时（技术暂停时冻结，主持人可暂停）；行程时长仍只显示游戏时间，不显示整局真实时长或限时。连接恢复不显示秒数。个人实时位置是服务器确认的游戏区间进度，不是地理GPS坐标，也不会显示给其他人。估算时长与起点组合仍待真人试玩校准。

公开页面和一般主持端从服务端只收到公共字段；私人身份、手牌、行程、侵蚀、掷骰和保护状态不会先传到大屏再隐藏。每部手机只收到自己的私密信息。结束后才释放回放与日志。公示到站信息仍允许合法推理。

## 接入图标和 CG

现已按车厢与旅行手帖方案改版：候车大厅与首页共用带角色的标题插画和左侧内容布局，窄屏时插画在上、内容在下；手机选路／窗景、结局和行程回放使用独立布局。背景图、标题页、四张头像和三张结局 CG 已从根目录 `assets/` 导出到 `public/assets/`，以 WebP 本地加载；原始导出图片与 PSD 保留。

更新根目录 `assets/` 中的素材后，运行 `python tools/prepare_art.py` 重新生成网页用图（需要 Pillow）。路径由 [素材清单](public/assets/manifest.json) 管理。完整插槽说明见 [美术接入说明](public/assets/README.md)。修改后刷新页面生效；不需要改游戏逻辑。

头像：`avatar0` 用于未知身份，其余用于莲子、梅莉、紫。CG：01 相逢，02 紫获胜（含侵蚀诱导），03 超时／未相逢。CG03 使用现有 `draw` 插槽，累计游戏时间超过48小时仍未结束时自动显示。缺图继续显示占位，不影响操作。

## 文件与存档

每局结束时立即写入独立 JSON 日志，默认位于 `runtime/logs/`，无需关闭后端；同组重开保留上一局文件。日志包含现实开局／发车／结束时间、游戏内显示时刻、实际持续秒数、各类暂停耗时、逐轮决策与提交时间、路线／改签／留站、断线及玩家统计。主持端“导出本局”使用同一结构。字段与异常恢复口径见[对局日志说明](design/对局日志说明.md)。

- `run.py`：Python 启动入口；`server/game.py`：规则引擎；`server/web.py`：房间服务与授权。
- `server/data.py`：读取原有百站数据与地图，剔除设计示意中的假计时与假玩家标记。
- `public/`：浏览器界面、玩法说明及素材插槽；不需要构建步骤。
- `design/`：已有设计资料，保留原稿。
- `runtime/`：本机私密房间快照，每秒及每次操作保存，不通过网页暴露，不纳入版本控制。内含凭证和未公开事件，不要在对局中展示或分享。

主机进程异常退出后，重新启动会保留房间与凭证，并将中断中的对局标为中止；不会根据不完整墙钟时间猜测续局。已正常结束的回放可以恢复。导出日志只包含必要游戏记录，不含加入凭证。浏览器删除存储会失去原座位凭证，主持人可在开局前移除后重新加入；进行中无法抢占座位。

昼夜配色与时间显示回归：`python tests/browser_theme.py`。包含06:00／18:00切换、跨午夜、主屏与手机线路同色、特急剩余1小时显示为01:00。
