# 开发说明

## 从哪里开始

| 模块 | 职责 |
| --- | --- |
| `run.py` | 将可选 vendor 依赖加入搜索路径，启动 HTTP 服务 |
| `server/settings.py` | 读取 JSON 并校验字段、类型、概率和对白引用 |
| `server/data.py` | 读取路网，构造邻接表和线路，处理公开地图 SVG |
| `server/starts.py` | Dijkstra 最短路、起点距离检查与模板生成 |
| `server/dialogue.py` | 筛选对白候选、生成公开地点和已触发对白投影 |
| `server/game.py` | 权威规则、游戏推进、动作处理与公私状态投影 |
| `server/journal.py` | 现实时间记账和去除凭证后的日志结构 |
| `server/web.py` | HTTP 路由、凭证与来源校验、加锁、持久化和恢复 |
| `public/app.js` | 主持、大屏和手机界面、状态轮询、动作提交与回放 |

## 游戏状态与时间

房间流程为 `lobby → briefing → running ↔ decision → ended`。技术暂停保存在独立的 `technical` 字段中。`game.advance()` 根据单调时钟推进，`rail_step()` 结算游戏时间；日志墙钟时间只用于记录，不能反过来驱动游戏规则。

创建新房间时最多允许 12 个活动房间。未开始的候车大厅仅在最近 30 分钟内有主持人或玩家心跳时计入；重启后尚无人重新连接的旧大厅不占名额。身份分配后的未结束对局始终计入。此计数不删除或中止旧大厅，原房间码和凭证仍可恢复使用；不能用后台持续刷新的 `updated` 字段判断活跃状态。

玩家动作带版本与决策批次，陈旧选路抛出 `StaleAction`，客户端应重新获取选项。到站选路与接触结果确认合入同一个决策批次，只有全部必要待办完成才允许继续。主持人可为尚未选路的玩家安排留站，但不能跳过接触确认。系统不再提供请求他人留站的动作；玩家只可在本人的合法选路阶段选择留站，提交后不能撤回。HTTP 在持有房间锁时处理动作、保存快照；保存失败会恢复动作前状态。对局结束日志写入失败时保留已完成快照并重试，不回退胜负结果。

手机线路图直接解析 `/map.svg` 中的区间路径与 `config.lines` 颜色，不另存几何；大屏标记固定在车站上，被遮挡的站名标签临时平移。

`public_state()` 是公开字段白名单，`private_state()` 在此基础上补入单个玩家自己的信息。新加私密字段时，应在投影处明确控制可见性，不要把整个房间对象发送到浏览器。静态服务根目录始终为 `public/`。

公开玩家名单不包含位置。地图从 `markers` 读取目击；莲子首次接触堇子（`resolve_hat` 出现新接触，不论是否换帽）之前，棕色标记带公开字母 `label` 与座位 `seat`；之后房间的 `brownAnonymous` 置位，棕色标记两者都不再输出，不能连接回座位或角色。真实交会时同时重分配匿名标识、字母与目击时刻，避免用标识或记录年龄识别离站分支。字母按随机标识排序分配，跳过地图上仍在显示的字母，不能按座位顺序发放。公开到站历史也不携带棕色玩家编号。待确认信息提供 `pendingCount`，以及 `pendingSeats`：只列出地图上本就公开座位的待选路玩家（紫色始终可列，棕色仅在 `brownAnonymous` 置位前），接触确认的参与者从不列名。大屏用目击列表的“选路中”标记和地图光圈指出这些座位，主持端状态栏把其余人数写作棕色旅人；屏幕中央的卡片位置留给旅途回声。梅莉私密的 `renkoLastArrival` 仅含真实莲子上次停靠的站点与时刻。

堇子可重复出现，`by_role()` 只返回三名唯一主角；处理堇子时遍历玩家列表。接帽资格和是否被真正的紫接触只存服务端；接触后不移出普通行动、接触确认或网络暂停名单。结局为秘封胜且至少一名堇子未被真正的紫接触时，全体堇子共同获胜，包括曾被抓者；全被抓不提前结束或公开状态。梅莉无论是否侵蚀都只封锁接帽，不计作真正的紫抓捕；侵蚀本身仍然永久。

区分两种接触口径：会合、捕获和紫色角色封锁仍要求实际停靠同站；莲子与堇子的换帽接触允许任一方在同一结算时刻到达或不停站经过同一游戏节点。过去的目击标记重合、区间擦肩均不算真实接触。接触确认暂停不改变列车停靠状态，不改写 `lastArrival` 或梅莉的历史停站记录；仅堇子之间相遇不产生此暂停。

按莲子—堇子配对跟踪持续接触，同一对未分离前不重复抽签或暂停。新堇子加入产生新接触，已有配对不重抽。一次结算中若有多名新接触堇子，先从本次新接触者中随机选一名，再检查帽子是否在莲子手中、对象资格、冷却和次数，并以50%概率换帽；不依据隐藏资格预先过滤，也不在失败后寻找替补。接触批次中的参与者均须确认。无论失败原因是什么，都走同样的暂停与统一“本次未换帽”反馈，不能用候选名单、待办差异或原因文本泄露资格。

先结算堇子与紫色角色的实际停靠接触和强制归还，再判核心胜负；只有未结束时才处理自然到期、新接触和自动借帽。归还清除旧到期时间，重复接触不能刷新冷却。借帽成功才消耗一次，最多2次；借戴最多8刻，归还后冷却4刻，所有暂停均不消耗时长。取消帽子预设操作，确认动作仍须防陈旧和重复提交，存档保留持续接触、未完成确认和借戴状态，赛后日志记录完整接触、抽签及帽子事件。实时投影不发送隐藏资格、失败原因、随机候选或完整换帽事件。

## 内容与代码

固定对白和数值修改优先使用 `config/`；无需在规则分支中寻找文字。字段和单位见 [配置说明](configuration.md)。`design/` 仅为本机设计资料，不再参与运行时读取。

Python 源码按 `pyproject.toml` 中的 Black 配置格式化；前端保持普通 ES module，无需构建。可选维护命令：

```sh
python -m pip install black==26.5.1
python -m black server run.py tools tests
npx --yes prettier@3.6.2 --write public/app.js public/index.html
```

Node.js 仅用于可选的格式化，不是游戏依赖。修改规则或网络服务后运行 `python -m unittest discover -s tests -v`；修改前端后运行相关 `tests/browser_*.py`。测试使用临时数据目录，不要将测试进程指向真实 `runtime/`。

发布包采用 `tools/release-files.txt` 文件白名单。新增运行依赖文件后，将其加入清单，并解压发布包运行测试，避免本机私有文件掩盖缺失依赖。
